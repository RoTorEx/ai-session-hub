# FleetScope

Локальный Rust CLI/TUI для обзора уже запущенных интерактивных Codex и Claude
в iTerm2 и перехода в точную существующую панель. Обычный запуск агентов не
меняется. FleetScope ничего не вводит в панели и не управляет процессами агентов.

## Установка

Требования: macOS Apple Silicon, iTerm2; Rust нужен только для сборки из исходников.
Проверенная среда: macOS 26.6.1, iTerm2 3.7.3.

```sh
make install-local
fleet-scope
```

Бинарник устанавливается в `~/.x-cli-fleet-scope/bin/fleet-scope`; установщик
добавляет управляемый PATH-блок в `.zshrc` или `.bashrc`. В уже открытом shell:

```sh
export PATH="$HOME/.x-cli-fleet-scope/bin:$PATH"
fleet-scope --version
```

После публикации первого релиза готовый бинарник можно установить без Rust:

```sh
curl -fsSL https://github.com/RoTorEx/fleet-scope/releases/latest/download/fleet-scope-install.sh | sh
fleet-scope update
```

Установщик и updater проверяют SHA-256 и версию и заменяют бинарник атомарно.
Повторная установка сохраняет конфигурацию. Если релиза ещё нет или загрузка
не удалась, update завершится с ошибкой, сохранив установленный бинарник.

При первом обращении macOS может запросить Automation-доступ к iTerm2. Если
он запрещён, FleetScope показывает причину отсутствия связи и не делает Jump.
Разрешение можно изменить в System Settings → Privacy & Security → Automation
для приложения, из которого запускается команда. Python API, shell integration,
hooks и запуск FleetScope до агентов не требуются.

## Команды

```sh
fleet-scope                    # двухпанельный обзор
fleet-scope list                # свежий список и выход
fleet-scope --plain             # тот же список
fleet-scope list --json         # массив сессий для скриптов
fleet-scope jump SESSION_ID     # идентификатор из списка
fleet-scope version             # также -V / --version
fleet-scope update
fleet-scope setup-config        # создать отсутствующий config
fleet-scope themes
fleet-scope theme ocean
fleet-scope benchmark --samples 20 # локальный benchmark, без Jump
fleet-scope --help
```

Без интерактивного терминала запуск без аргументов печатает справку.
help/version/setup-config/themes/theme не требуют работающего iTerm2. Ошибки дают ненулевой код;
диагностика идёт в stderr, JSON — только в stdout.

В JSON `id` — PID и время запуска экземпляра, `provider` — codex/claude,
`cwd` — фактическая директория, `project` — корень Git worktree либо директория,
`status` — Live. `location` содержит UUID панели, TTY, окно и номера вкладки/
панели с нуля; при неподтверждённой связи это null, причина — `link_reason`.
ID действителен только пока жив этот экземпляр; номера вкладок не являются ID.
В обычном интерфейсе номера отображаются с единицы.

## Управление

| Клавиша | Действие |
|---|---|
| ↑/↓, j/k | Выбрать сессию; заголовки групп пропускаются |
| Tab | Переключить фокус сессий/деталей |
| ← / → | Фокус сессий / деталей |
| Колесо мыши | Прокрутить панель под указателем |
| PageUp/PageDown, Home/End | Прокрутить панель с фокусом |
| Enter/o | Проверить связь и перейти в существующую панель |
| e | Раскрыть/свернуть длинные сообщения |
| m | Показать/скрыть технические идентификаторы |
| / | Поиск по агенту, проекту, пути и названиям |
| Enter при поиске | Применить фильтр |
| Esc при поиске | Очистить фильтр и закрыть поиск |
| r | Обновить расположение панелей и контент |
| ? | Справка |
| q / Ctrl+C | Выход |
| Esc | Закрыть справку/поиск, иначе выход |

Основные буквенные клавиши работают и в русской раскладке. В поиске буквы
вводятся как текст. Для очистки применённого фильтра нажмите `/`, затем Esc.

Слева — сессии под заголовками проектов. Сессии подпапок одного Git worktree
собраны вместе, разные worktrees разделены. Заголовки нельзя выбрать.
Справа — блоки STATUS, TERMINAL & SESSION, LATEST EXCHANGE и RECENT HISTORY.
Версия постоянно видна в верхней строке. Цветовые акценты — как в gtd; classic
использует тёмный текст выделения для контраста с синей палитрой iTerm2.

Для прокрутки деталей наведи на них мышь и используй колесо. С клавиатуры:
**Tab → ↑/↓ или PageDown**. Полоса прокрутки показывает положение. **e** раскрывает
длинные запросы/ответы, **m** показывает PID, ID и TTY. Дублирующиеся пути не
повторяются: Folder — текущая папка процесса, Git root — корень проекта, если
он отличается. Выбор и прокрутка сохраняются при обновлении.

После Jump обзор остаётся открытым; вернуться можно обычной навигацией iTerm2.
После выхода FleetScope ничего не мониторит.

## Настройки и темы

Config: `$XDG_CONFIG_HOME/fleet-scope/config.toml` либо
`~/.config/fleet-scope/config.toml`. `FLEETSCOPE_CONFIG` переопределяет путь.
Отсутствующий файл не препятствует запуску: используются встроенные значения.

```toml
theme = "classic"
refresh_seconds = 2
content_seconds = 5
metadata_seconds = 30
```

Все интервалы должны быть положительными. `refresh_seconds` управляет лёгкой
проверкой процессов: новые/закрытые агенты обнаруживаются без постоянного полного
сбора метаданных. `metadata_seconds` — карта окон/вкладок и Git-корней; новый агент
или `r` обновляет её раньше. `content_seconds` — статус и история только выбранной
панели. При выборе другой сессии чтение начинается после короткой паузы 150 мс.
Перенос вкладки может некоторое время показывать прежнее расположение; Jump
всё равно разрешает актуальную панель по UUID. Он не ждёт очереди фонового сбора.

Обновление не переключает Live/Updating и не перерисовывает неизменившийся экран.
Подробные измерения и границы CPU-оценки — [docs/PERFORMANCE.md](docs/PERFORMANCE.md).
Повторить локально: `fleet-scope benchmark --samples 20`. Добавление
`--jump SESSION_ID` также измеряет реальные переходы и меняет выбранную панель.

Темы: classic, forest, sunset, ocean, midnight. `theme NAME` сохраняет остальные
настройки и комментарии. Тема применяется при следующем запуске TUI.

## Ограничения

Live означает существующий интерактивный процесс и включает ожидание команды
или подтверждения. Детали дополнительно читают маркеры статуса и текст из истории
выбранной панели iTerm2. Контент берётся из терминала, а не из найденного по
похожему пути архивного разговора. Он может быть неполным; роли и статус зависят
от формата Codex/Claude. Неизвестный формат показывает `activity unknown`.
Незавершённый нижний prompt исключается: это может быть ещё не отправленный текст.
Conversation ID не выдумывается.

В памяти остаётся только хвост снимка (65 536 символов), до 32 блоков по 8192 символа.
По умолчанию сообщение показывает начало (4 строки / 280 символов), `e` раскрывает
сохранённую часть. Это не полный архив переписки. FleetScope не сохраняет и не
отправляет контент наружу; чтение не влияет на безопасность идентификации Jump.

Поддерживаются локальные обычные панели iTerm2 и интерактивные Codex/Claude.
Неинтерактивные exec/print, служебные процессы и shell после завершения агента
не являются сессиями. SSH, tmux, другие терминалы и дополнительные провайдеры
не поддерживаются; неподтверждённые кандидаты могут отображаться как Unlinked.

Для обнаружения нужны доступные метаданные процесса и stdin, подключённый к
его TTY. Необычные обёртки или перенаправленный stdin могут препятствовать
обнаружению. Jump повторно проверяет процесс/панель и отказывает при неоднозначной
связи. Устаревшие данные после ошибки отмечены STALE. Проверки выполняются перед
переходом; завершение процесса после последней проверки остаётся возможной
гонкой, но переход по совпадению заголовка или старому индексу не выполняется.

Полный перезапуск iTerm2 с сохранением реальных пользовательских агентов ещё
не проверялся. Опубликованные v0.1.0 и v0.1.1 скачаны и проверены на этой машине:
self-update обновил 0.0.0 → 0.1.0 → 0.1.1, сохранил конфиг; повторный update
подтвердил актуальную версию. Опубликованный установщик также проверен в изоляции.
Подробные наблюдения — [docs/VALIDATION.md](docs/VALIDATION.md).

## Разработка и выпуск

```sh
make check          # формат без изменений, clippy, тесты, release-сборка, delivery checks
make run
make fmt
make version
make bench          # диагностические замеры без Jump
make smoke-install  # упаковка и изолированная установка
make release        # интерактивный запрос MAJOR.MINOR.PATCH на чистой main
make release-push   # отдельная отправка ветки и annotated tag
```

`make release` обновляет Cargo.toml/Cargo.lock/CHANGELOG.md и создаёт release
commit и тег, но ничего не публикует. Отправка тега запускает GitHub Actions:
сборка Apple Silicon, smoke-install, архив + checksum + установщик, GitHub Release.
Цель — публичный `RoTorEx/fleet-scope`; версия берётся из Cargo.toml и проверяется
против тега. Выпуск требует отдельного одобрения.

Перед первым выпуском или изменением workflow проверьте его через `actionlint
.github/workflows/release.yml`, затем выполните `make smoke-install`. Это проверяет
допустимые контексты GitHub Actions и реальную упаковку/установку до отправки тега.

Если публикация существующего тега не началась из-за ошибки workflow, исправьте
workflow на main и запустите `gh workflow run release.yml --ref main -f tag=vX.Y.Z`.
Ручной запуск собирает именно существующий тег и проверяет его версию и commit;
переписывать тег не нужно. Обычные следующие выпуски запускаются отправкой тега.

Сборки хранятся в `~/construction_side/fleet-scope/target`, упаковка — в `dist`
рядом. Эти каталоги можно удалить: исходники, установленный бинарник и конфигурация
от них не зависят. Повторная сборка создаст их заново.

## Удаление

Удалите `~/.x-cli-fleet-scope` и управляемый блок между `# x-cli-fleet-scope`
и `# /x-cli-fleet-scope` из shell-профиля. При необходимости отдельно удалите
выбранный config и `~/construction_side/fleet-scope`. Агентные процессы и их
данные не затрагиваются.

Продуктовые правила — BUSINESS.md; локальные агентные инструкции — AGENTS.md;
порядок этапов — ROADMAP.md. Проверки выполняются лично, без субагентов.
