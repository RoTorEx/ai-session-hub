# Sova

Локальный Rust CLI/TUI для обзора уже запущенных интерактивных Codex и Claude
в iTerm2 и перехода в точную существующую панель. Обычный запуск агентов не
меняется. Sova ничего не вводит в панели и не управляет процессами агентов.

## Установка

Требования: macOS Apple Silicon, iTerm2; Rust нужен только для сборки из исходников.
Проверенная среда: macOS 26.6.1, iTerm2 3.7.3.

```sh
make install-local
sova
```

Бинарник устанавливается в `~/.x-cli-sova/bin/sova`; установщик
добавляет управляемый PATH-блок в `.zshrc` или `.bashrc`. В уже открытом shell:

```sh
export PATH="$HOME/.x-cli-sova/bin:$PATH"
sova --version
```

Готовый бинарник можно установить без Rust:

```sh
curl -fsSL https://github.com/RoTorEx/sova/releases/latest/download/sova-install.sh | sh
sova update
```

Установщик и updater проверяют SHA-256 и версию и заменяют бинарник атомарно.
Повторная установка сохраняет конфигурацию. Если релиза ещё нет или загрузка
не удалась, update завершится с ошибкой, сохранив установленный бинарник.

При первом обращении macOS может запросить Automation-доступ к iTerm2. Если
он запрещён, Sova показывает причину отсутствия связи и не делает Jump.
Разрешение можно изменить в System Settings → Privacy & Security → Automation
для приложения, из которого запускается команда. Python API, shell integration,
hooks и запуск Sova до агентов не требуются.

## Переход с FleetScope

Начиная с 0.2.0 команда называется `sova`. Установите её через новый установщик
выше: старый `fleet-scope update` не выполняет переход между именами пакетов.
Если конфигурации Sova ещё нет, установщик копирует настройки из
`~/.config/fleet-scope/config.toml` (с учётом `XDG_CONFIG_HOME`). Существующий
config Sova и явно заданный `SOVA_CONFIG` имеют приоритет. Старый config остаётся
на месте до проверки новой установки.

После проверки `sova --version` удалите старый бинарник
`~/.x-cli-fleet-scope/bin/fleet-scope` и старый блок `# x-cli-fleet-scope` …
`# /x-cli-fleet-scope` из shell-профиля. В уже открытом shell добавьте новый
PATH, как показано выше, или откройте новый терминал. Исходники теперь находятся
в каталоге `sova`; старые теги и релизы сохраняют исходные имена файлов.

## Команды

```sh
sova                    # Sessions | Details; f → History | Content
sova list                # свежий список и выход
sova --plain             # тот же список
sova list --json         # массив сессий для скриптов
sova jump SESSION_ID     # идентификатор из списка
sova version             # также -V / --version
sova update
sova setup-config        # создать отсутствующий config
sova themes
sova theme ocean
sova benchmark --samples 20 # локальный benchmark, без Jump
sova --help
```

Без интерактивного терминала запуск без аргументов печатает справку.
help/version/setup-config/themes/theme не требуют работающего iTerm2. Ошибки дают ненулевой код;
диагностика идёт в stderr, JSON — только в stdout.

В JSON `id` — PID и время запуска экземпляра, `provider` — codex/claude,
`cwd` — фактическая директория, `project` — корень Git worktree либо директория,
`status` — Live. `location` содержит UUID панели, TTY, окно и номера вкладки/
панели с нуля; при неподтверждённой связи это null, причина — `link_reason`.
ID действителен только пока жив этот экземпляр; номера вкладок не являются ID.
В обычном интерфейсе номера отображаются с единицы.

## Управление

| Клавиша | Действие |
|---|---|
| ↑/↓, j/k | Выбрать сессию/итерацию; справа прокрутить текст |
| f | Переключить Sessions \| Details ↔ History \| Content |
| Tab / Shift+Tab | В режиме истории переключить фокус History ↔ Content |
| ← / → | Предыдущая/следующая сессия или итерация |
| Колесо мыши | Навигация в панели под указателем без смены фокуса |
| PageUp/PageDown, Home/End | Навигация активной панели |
| Enter в Sessions / o | Проверить связь и перейти в существующую панель |
| e / Enter в History | Фокус в Content для прокрутки; e возвращает в History |
| t | Следующая цветовая тема, сразу применить и сохранить |
| / | Поиск по агенту, проекту, пути и названиям |
| Enter при поиске | Применить фильтр |
| Esc при поиске | Очистить фильтр и закрыть поиск |
| r | Обновить расположение панелей и контент |
| ? | Справка |
| q / Ctrl+C | Выход |
| Esc | Закрыть справку/поиск; из истории вернуться к Sessions, иначе выход |

Основные буквенные клавиши работают и в русской раскладке. В поиске буквы
вводятся как текст. Для очистки применённого фильтра нажмите `/`, затем Esc.

Две колонки занимают всю доступную высоту: слева 40%, справа 60%.
При запуске это **Sessions | Details**. **f** меняет обе панели на
**History | Content** выбранной сессии; повторное **f** возвращает список сессий.
Минимальный размер терминала — 50×12, в узком окне сохраняются две колонки.

Группы показывают имя папки; одинаковые имена различаются родительской папкой.
Полные пути остаются в Details. Там же видны название сессии, окно, вкладка,
панель, Folder и идентификаторы. Секции разделены линиями.
Имя берётся из терминального заголовка; оно может отличаться от имени чата агента.
Sova не переименовывает чаты или вкладки: это остаётся в агенте/iTerm2.

При запуске фокус на Sessions. В режиме истории **Tab / Shift+Tab** переключает
History и Content для прокрутки полного текста. Details не получает фокус,
метаданные можно прокрутить колесом. Активную панель обозначают спокойная
цветная рамка и имя внизу. Клик фокус не меняет.
В режиме истории над панелями остаются имя сессии, провайдер, статус и папка.
**o** в любом режиме открывает её точную панель iTerm2. **/** возвращает список
сессий для поиска. Переключение режимов сохраняет выбранную сессию и итерацию.

History объединяет запрос и следующие за ним ответы и действия в одну итерацию,
до следующего запроса. Если начало не попало на экран, оставшийся ответ показан
как неполная итерация. Запрос без ответа также остаётся видимым.
Старые итерации сверху, свежие снизу. При переключении сессии выбрана верхняя
итерация, прокрутка истории сбрасывается вверх.
↑/↓ выбирают итерацию; превью каждого сообщения содержит первые **100 символов**.
Полный текст выбранной итерации автоматически показан справа в Content.
Стрелки в History выбирают итерации; **Tab** или **e / Enter** переносит фокус
в Content для прокрутки. **e / Tab** возвращает фокус в History.
**Esc / f** возвращает обе панели в Sessions | Details.
Время сообщений не угадывается.
Это снимок видимого экрана терминала, а не полный архив разговора.
Версия и название темы постоянно видны сверху, **t** меняет палитру сразу.
По умолчанию используется спокойная тема **calm**, остальные темы доступны.

После Jump обзор остаётся открытым; вернуться можно обычной навигацией iTerm2.
После выхода Sova ничего не мониторит.

## Настройки и темы

Config: `$XDG_CONFIG_HOME/sova/config.toml` либо
`~/.config/sova/config.toml`. `SOVA_CONFIG` переопределяет путь.
Отсутствующий файл не препятствует запуску: используются встроенные значения.

```toml
theme = "calm"
refresh_seconds = 2
content_seconds = 5
activity_seconds = 10
metadata_seconds = 30
```

Все интервалы должны быть положительными. `refresh_seconds` управляет лёгкой
проверкой процессов: новые/закрытые агенты обнаруживаются без постоянного полного
сбора метаданных. `metadata_seconds` — карта окон/вкладок и Git-корней; новый агент
или `r` обновляет её раньше. `activity_seconds` — компактные статусы всех связанных
сессий (10 секунд по умолчанию). `content_seconds` — полный контент выбранной
панели, который читается только в режиме History (5 секунд). Статусный скан не
перечитывает карту окон или Git-корни. При входе в History чтение начинается сразу
после короткой паузы 150 мс, без ожидания полного интервала.

При потере терминального фокуса Sova приостанавливает фоновые опросы. Возврат
фокуса сразу обновляет процессы, расположение, статусы и открытый контент.
Это работает через события фокуса iTerm2, без дополнительного опроса видимости;
если терминал не присылает события, обновления продолжаются. Пауза срабатывает
и при переходе в соседнюю панель, даже если Sova ещё видна. Завершения и ручные
посещения агентов во время паузы могут быть пропущены; `o` по-прежнему сразу
отмечает подтверждённый переход.

После **60 секунд без пользовательской активности** Sova засыпает даже в видимой
панели: прекращает фоновые опросы и завершает оба `osascript`, освобождая их
память. В шапке появляется `SLEEP`. Клавиатура, мышь или возврат фокуса прогревают
помощников и обновляют данные. Первое действие после сна может занять больше
времени. Обновления статусов и ответы агентов не считаются активностью пользователя.
Текущий запрос может завершиться перед отключением. При выходе все помощники
завершаются; выход из сна не запускает их ради завершения программы.
Перенос вкладки может некоторое время показывать прежнее расположение; Jump
всё равно разрешает актуальную панель по UUID. Он не ждёт очереди фонового сбора.

Обновление не переключает Live/Updating и не перерисовывает неизменившийся экран.
Подробные измерения и границы CPU-оценки — [docs/PERFORMANCE.md](docs/PERFORMANCE.md).
Повторить локально: `sova benchmark --samples 20`. Добавление
`--jump SESSION_ID` также измеряет реальные переходы и меняет выбранную панель.

Темы: calm (по умолчанию), classic, forest, sunset, ocean, midnight. `theme NAME` сохраняет остальные
настройки и комментарии. CLI-команда применяет тему при следующем запуске; клавиша `t` в TUI — сразу.

## Статусы в списке сессий

| Символ | Значение |
|---|---|
| ● | Агент работает |
| ○ | Idle — ждёт следующей команды |
| ! | Требуется подтверждение |
| ? | Вопрос или действие от пользователя |
| × | Агент сообщил о блокере |
| ◆ | Новый ответ готов; панель ещё не наблюдалась открытой |
| ✓ | Панель открыли после готовности ответа |
| · | Активность неизвестна |

Вопросы и блокеры распознаются по явным фразам видимого ответа; это эвристика.
Текст запроса/ответа находится в History, расшифровка статуса — в Details, легенда — в `?` help.
Вопрос/блокер остаётся отмеченным после открытия панели.

Sova отслеживает открытие точной активной панели в foreground iTerm2 или
успешный Jump. Выделение строки и просмотр Details не считаются открытием.
Это не подтверждение прочтения. История отслеживается только пока Sova
работает: уже завершённые до запуска ответы, быстрые задачи/посещения между
сканами и скрытые за пределами экрана маркеры могут остаться неизвестными.

## Ограничения

Live означает существующий интерактивный процесс и включает ожидание команды
или подтверждения. Детали дополнительно читают маркеры статуса и текст видимого экрана
выбранной панели iTerm2. Контент берётся из терминала, а не из найденного по
похожему пути архивного разговора. Он может быть неполным; роли и статус зависят
от формата Codex/Claude. Неизвестный формат показывает `activity unknown`.
Незавершённый нижний prompt исключается: это может быть ещё не отправленный текст.
Conversation ID не выдумывается.

В памяти остаётся только хвост снимка (65 536 символов), до 32 блоков по 8192 символа.
По умолчанию сообщение показывает начало (4 строки / 280 символов), `e` раскрывает
сохранённую часть. Это не полный архив переписки. Sova не сохраняет и не
отправляет контент наружу; чтение не влияет на безопасность идентификации Jump.

Поддерживаются локальные обычные панели iTerm2 и интерактивные Codex/Claude.
Неинтерактивные exec/print, служебные процессы и shell после завершения агента
не являются сессиями. SSH, tmux, другие терминалы и дополнительные провайдеры
не поддерживаются; неподтверждённые кандидаты могут отображаться как Unlinked.

Для обнаружения нужны доступные метаданные процесса и stdin, подключённый к
его TTY. Необычные обёртки или перенаправленный stdin могут препятствовать
обнаружению. Jump повторно проверяет процесс/панель и отказывает при неоднозначной
связи. Устаревшие данные после ошибки отмечены STALE. Проверки выполняются перед
переходом; завершение процесса после последней проверки остаётся возможной
гонкой, но переход по совпадению заголовка или старому индексу не выполняется.

Полный перезапуск iTerm2 с сохранением реальных пользовательских агентов ещё
не проверялся. Опубликованные v0.1.0 и v0.1.1 скачаны и проверены на этой машине:
self-update обновил 0.0.0 → 0.1.0 → 0.1.1, сохранил конфиг; повторный update
подтвердил актуальную версию. Опубликованный установщик также проверен в изоляции.
Подробные наблюдения — [docs/VALIDATION.md](docs/VALIDATION.md).

## Разработка и выпуск

```sh
make check          # формат без изменений, clippy, тесты, release-сборка, delivery checks
make run
make fmt
make version
make bench          # диагностические замеры без Jump
make smoke-install  # упаковка и изолированная установка
make release        # интерактивный запрос MAJOR.MINOR.PATCH на чистой main
make release-push   # отдельная отправка ветки и annotated tag
```

`make release` обновляет Cargo.toml/Cargo.lock/CHANGELOG.md и создаёт release
commit и тег, но ничего не публикует. Отправка тега запускает GitHub Actions:
сборка Apple Silicon, smoke-install, архив + checksum + установщик, GitHub Release.
Цель — публичный `RoTorEx/sova`; версия берётся из Cargo.toml и проверяется
против тега. Выпуск требует отдельного одобрения.

Перед первым выпуском или изменением workflow проверьте его через `actionlint
.github/workflows/release.yml`, затем выполните `make smoke-install`. Это проверяет
допустимые контексты GitHub Actions и реальную упаковку/установку до отправки тега.

Если публикация существующего тега не началась из-за ошибки workflow, исправьте
workflow на main и запустите `gh workflow run release.yml --ref main -f tag=vX.Y.Z`.
Ручной запуск собирает именно существующий тег и проверяет его версию и commit;
переписывать тег не нужно. Обычные следующие выпуски запускаются отправкой тега.

Сборки хранятся в `~/construction_side/sova/target`, упаковка — в `dist`
рядом. Эти каталоги можно удалить: исходники, установленный бинарник и конфигурация
от них не зависят. Повторная сборка создаст их заново.

## Удаление

Удалите `~/.x-cli-sova` и управляемый блок между `# x-cli-sova`
и `# /x-cli-sova` из shell-профиля. При необходимости отдельно удалите
выбранный config и `~/construction_side/sova`. Агентные процессы и их
данные не затрагиваются.

Продуктовые правила — BUSINESS.md; локальные агентные инструкции — AGENTS.md;
порядок этапов — ROADMAP.md. Проверки выполняются лично, без субагентов.
